# CSS в подсказках daisyUI-классов

Сервер отдаёт daisyUI-классы для поля классов через `GET /api/classes/components`. Найдено при проверке этапа 5.

## Критерии готовности

- [x] У 185 из 686 классов пустой `css` (например btn-outline, btn-active, btn-disabled, card-sm, collapse, divider-primary, avatar-online), при наведении нет превью. Разобраться в извлечении на сервере
- [x] Превью `btn-md` показывает правило, вложенное само в себя: `.btn-md { .btn-md { ... } }`
- [x] Тест на извлечение CSS для этих классов

## Причины (30.10.2026)

- Правила на несколько селекторов (`.btn-outline,.btn-dash{…}`) не считаются правилом класса: сравнивается весь селектор целиком. Отсюда пустой CSS у btn-outline, btn-active и других.
- У части классов нет правила только для себя, есть лишь составные: `.card-sm .card-body`, `.avatar-online:before`, `.divider-primary:before`. Их нужно показывать с полным селектором.
- Вложение `.btn-md { .btn-md { … } }` — похоже, CSS оборачивается в селектор дважды: на сервере и на клиенте.

## Итог (30.10.2026)

- Список селекторов делится по запятым верхнего уровня (`:where(a, b)` не режется), каждая часть `.name` считается правилом класса. Функция `splitSelectorList` в `packages/theme/src/classCompletion.ts`.
- Если своего правила нет, показываются до 4 самых коротких правил с этим классом (не больше 20 объявлений), например `.card-sm .card-body { … }`.
- Двойная обёртка была на клиенте: `useClassIndex.ts` снова прогонял готовый блок через разбор правил. Теперь готовые превью передаются в `loadClassIndex` напрямую.
- Пустых превью было 185 из 686, стало 0. Тест на настоящем `daisyui.css`. Каталог использует тот же код, его тесты проходят.
